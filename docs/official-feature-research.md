# 官网专业版能力与自部署实现评估

研究日期：2026-10-18。依据：官网公开页面、更新日志、开源仓库及 iztro 官方文档。
未登录官网会员账户，未测试会员内实际结果，未获取私有后端源码或提示词。
下文将已确认事实与建议实现区分；相同功能不代表相同私有算法或相同答案。

## 已确认的结构

- 开源仓库提供排盘算法、四化、格局、时间校正、流派配置、运限上下文、古籍原文及部分合盘知识。
- 完整断语库、线上后端 API、用户系统与商业界面不在开源范围。
- 官方 v4 数据由排盘引擎和断语库确定性生成，不经过 AI。
- 官网另有 AI 问盘、自有模型、合盘追问、命盘报告等交互；这部分并非只需读取预生成文本。
- 官网更新日志 2026-10-17—18 记载新增四化、煞星对开头论断的影响及文案校正；本站 10 月 15 日数据并未包含这些后续修改。

可据此推断官网在产品层面将“结构化排盘”“规则内容”“模型问答”组合使用，
但数据库结构、缓存策略、完整提示词及内部检索方式均无法由公开资料确认。

## 功能逐项评估

| 能力 | 当前基础 | 建议实现与限制 |
|---|---|---|
| 十三维本命解读 | 已导入 674,976 张命盘 | 保留原数据版本；不冒充官网最新规则输出 |
| AI 单盘问答 | ChatPanel / InsightPanel 有请求与流式显示代码，缺后端 | 服务器重新排盘，提供相关主题解读和可靠古籍片段，自行编写提示词后调用模型 |
| AI 双人合盘 | /heming 表单、双盘生成、合盘知识与评分参考在仓库 | 增加关系类型、并排命盘、结构化对比、模型分析和连续追问；评分需说明本地规则，不能承诺等同官网 |
| 六层运限 | 现有本命/大限/流年界面、yunxian-context 及 iztro | 补月/日/时上下文与显示；明确换年换月、闰月、子时等口径并验证；动态解读需新规则或 AI |
| 流派设置 | wenmo-config 有配置数据 | 接入界面、分享和服务器计算；自定义流派不能直接套固定数据集，至少需标注或停止匹配 |
| 报告导出 | 分享卡片和 html2canvas 基础组件 | 整理命盘图、十三维内容、来源和可选 AI 回答，增加打印版与 PNG；不依赖模型 |
| 命盘配置匹配 | 可重新计算有限范围的全部命盘 | 离线生成星曜/宫位等结构指纹并建立索引；单靠 v4 的 ms 字段无法精确比较全盘 |
| 命运双胞胎人数/地点 | 官网说明为人口估算与钟表时段换算 | 相似配置可自行实现；人数估算需另有明确人口数据与方法，不表示真人档案 |
| 三纪课程、字幕、批注 | 仓库有部分介绍与《天纪》语料 | 阅读、搜索、时间戳跳转技术可重做，但完整视频、字幕及官方专属批注没有随仓库完整提供 |
| 古籍精解 | 仓库包含三部古籍原文 | 可做自有学习笔记和明确标注的 AI 释义；不等于官网六部古籍四层精解及私有批注 |
| 会员/支付 | 仓库无完整实现 | 个人部署可直接开放自有功能；多人使用时另做登录、密钥隔离和额度控制 |

## 推荐的 AI 数据流程

1. 前端提交原始出生信息、明确的排盘设置、目标时间、主题和问题。
2. 服务器校验并重新排盘，不信任客户端提交的星曜和四化。
3. 生成精简的结构化命盘事实：相关宫位、主辅星、亮度、四化、三方四正及运限。
4. 本命问题在口径兼容时查询已导入的对应命盘和相关主题。运限问题重新计算上下文，
   不把数据集里冻结的“当前大限”等内容作为今天的事实。
5. 按宫位、主星与问题检索可信古籍/知识片段，只附带所需材料。
6. 向用户指定模型发送规则、证据、问题及适量对话历史，流式返回答案。
7. 界面区分“排盘事实”“数据集原文”“AI 解释”；只有存在对应原文时才展示引文及出处。

无需一开始训练模型或为 877 万段全文建立向量库。精确命盘匹配已有键，
古籍可先按关键词、主星、宫位检索；检索质量确有不足时再增加向量检索。
把整张盘全部十三维长文无差别发送，会增加费用和上下文噪声。

## 接口与部署建议

- 为当前个人部署配置一个服务端模型网关：协议、Base URL、模型名、API Key。
- 密钥运行时注入，不写进 Git、Docker 镜像、网页脚本或 NEXT_PUBLIC_* 变量。
- 增加单盘问答及双盘分析后端。可以兼容原 /api/interpret、/api/heming 前端，
  但需修正原流解析代码：网络 chunk 不保证按行到达，必须缓存未完成的 SSE 帧。
- 支持取消、超时、明确的额度/余额错误、输出中断提示和续写；限制输入、历史及输出长度。
- 对话按命盘/双方命盘及关系类型保存到本地；发往模型的生辰、问题与上下文仍会交给模型服务商处理。
- 如果以后多人访问，须增加访问控制和每用户配额，避免共用服务器密钥被随意消耗。

## 建议实施顺序

1. AI 单盘问答：直接利用已导入数据与现有排盘；保留原来的十三维阅读功能。
2. 双人合盘：统一生辰校正、双盘对照、关系类型、分析与追问。
3. 运限完整化：补月/日/时、选择器及上下文联动，再接动态 AI 解释。
4. 全盘报告：优先实现可打印页面和命盘 PNG，再完善阅读排版。
5. 结构相似命盘索引与古籍研读；课程内容另按可用资料决定。

模型服务信息确定后，应先做小规模真实接口验证；不预设模型名称、费用或官方效果一致性。
